Self-Hosting Open Historia

Build the Open Historia web build and serve it yourself — for offline play, your LAN, or friends over the internet. No Node server required.

Why Self-Host?

Open Historia is a self-hostable grand strategy game. The web build is a static site — all the game logic runs in your browser, and your saves and scenarios stay in your browser's storage. There are no central game servers, no accounts, and no cloud dependencies.

  • Offline play: Once built and served locally, no internet is required — play single-player anywhere.
  • LAN: Serve the build on your machine and friends on the same network open it in their browsers.
  • Remote play: Expose the build over a tunnel or domain to play with friends across the internet.
  • Full control: You control saves, scenarios, and AI configuration.
  • Privacy: No telemetry, no analytics, no accounts. Your game data stays in your browser.

Quick Setup: Self-Hosting in 3 Steps

Step 1 — Clone and install

Clone the repository and install dependencies with bun:

git clone https://github.com/Open-Historia/open-historia.git
cd open-historia
bun install
Step 2 — Build the web build

Produce the static site:

bun run build:web

This writes a complete, self-contained site to dist-web/. (Use bun run build:site if you want the assembled landing-page + game layout that dist-site/ produces.)

Step 3 — Serve the site

Serve dist-web/ with any static file server. The quickest option:

npx serve dist-web

Or copy dist-web/ to any static host (Vercel, Netlify, GitHub Pages, nginx, Caddy…). Players open the URL in their browser — on desktop or mobile — and the game runs entirely client-side.

For remote play over the internet, use a static host with HTTPS, or a tunnel like Tailscale or Cloudflare Tunnel to expose the local build.

Going Offline

Once built and served locally, Open Historia runs entirely offline — no internet connection needed. The game logic, map rendering, scenario data, and the entire UI are all local.

The one exception is the world-map tiles: the web build fetches them from the project's content nodes (checksum-verified). If you also host a content node locally, even that stays on your network.

Connecting an AI backend for diplomacy and events requires a local LLM (see the AI setup guide), but the game is fully playable without AI as a pure strategy sandbox with the map editor and scenario system.

Hosting & the AI Backend

The web build has no server of its own, so there's no port to forward and no server.js to run — just serve dist-web/ statically. If you expose it publicly, put it behind a reverse proxy (nginx, Caddy, Cloudflare) with HTTPS.

The AI features talk to a backend you configure — a local LLM (Ollama, LM Studio, llama.cpp) or an OpenAI-compatible cloud API. See the AI setup guide for details, including CORS headers your LLM server may need.

Running a Local Build as a Service

If you want the built site served automatically at boot, point a simple static-server unit at dist-web/. For example, a Linux systemd unit running npx serve -s dist-web, or point nginx/Caddy at the dist-web/ directory. No long-running Node game server is involved.
