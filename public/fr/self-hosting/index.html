Auto-hébergez Open Historia

Déployez votre propre instance d'Open Historia — le jeu de grande stratégie gratuit et open source. Le site est entièrement statique, il peut donc être hébergé n'importe où.

Prérequis

  • Node.js 18+ — requis pour compiler le projet
  • bun — le gestionnaire de paquets utilisé par le projet (bun.sh)
  • Git — pour cloner le dépôt

Compiler le site

Cloner et installer

git clone https://github.com/Open-Historia/open-historia.git
cd open-historia
bun install

Compiler le site statique

bun run build:site

Cela compile l'application web avec Vite, assemble le site statique complet (page d'accueil, guides, sitemap) et produit un dossier dist-site/ prêt à être servi par n'importe quel serveur web statique.

Tester localement

bun run preview:site

Sert le site compilé localement pour vérification avant déploiement.

Options de déploiement

Vercel (recommandé)

Vercel est la plateforme de déploiement la plus simple pour Open Historia. Le dépôt inclut un fichier vercel.json avec toutes les règles de réécriture nécessaires.

Forker et connecter

Forkez le dépôt sur GitHub, puis importez-le sur vercel.com. Vercel détecte automatiquement Vite.

Configurer le build

Définissez la commande de build sur bun run build:site et le répertoire de sortie sur dist-site. Installez bun via la variable d'environnement ENABLE_EXPERIMENTAL_COREPACK=1 ou utilisez l'image de build de Vercel avec bun préinstallé.

Déployer

Cliquez sur « Deploy ». Vercel gère le SSL, le CDN et les redéploiements automatiques à chaque push.

Netlify

Netlify fonctionne également très bien. Le dépôt inclut un fichier netlify.toml avec la configuration de build et les règles de redirection.

Connecter le dépôt

Sur netlify.com, créez un nouveau site depuis Git et sélectionnez votre fork.

Configurer le build

Commande de build : bun run build:site. Répertoire de publication : dist-site. Ajoutez la variable d'environnement BUN_VERSION ou utilisez le plugin bun de Netlify.

Déployer

Netlify gère le SSL, le CDN et les déploiements continus automatiquement.

GitHub Pages

GitHub Pages est gratuit et fonctionne bien pour les sites statiques comme Open Historia.

Compiler le site

Exécutez bun run build:site localement pour générer le dossier dist-site/.

Configurer GitHub Pages

Dans les paramètres de votre fork, activez GitHub Pages et pointez-le vers la branche gh-pages ou utilisez une GitHub Action pour déployer automatiquement le dossier dist-site/.

Gérer le chemin de base

Si vous hébergez sous un sous-chemin (par ex. username.github.io/open-historia), définissez base dans vite.config.js sur le sous-chemin avant de compiler.

Docker

Pour les déploiements auto-hébergés, Docker avec nginx est une option solide.

Créer un Dockerfile

Utilisez une image node pour compiler, puis copiez le résultat dans une image nginx :

FROM node:20 AS build
WORKDIR /app
COPY . .
RUN npm install -g bun && bun install && bun run build:site
FROM nginx:alpine
COPY --from=build /app/dist-site /usr/share/nginx/html

Compiler et exécuter

docker build -t open-historia .
docker run -p 8080:80 open-historia

Tout serveur web statique

Le dossier dist-site/ est un site statique pur — HTML, CSS, JS et assets. Il peut être servi par n'importe quel serveur web : nginx, Apache, Caddy, ou même un simple python -m http.server pour les tests. Aucune configuration serveur spéciale n'est requise au-delà du fait de servir des fichiers statiques.
